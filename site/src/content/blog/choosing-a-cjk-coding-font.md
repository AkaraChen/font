在终端里写中文注释、在编辑器里读中文文档，选字体这件事上大多数人踩的坑是一样的：挑了一套好看的中文字体，结果表格错位、光标飘、图标压字。问题几乎从来不在字形，在**网格**。

## 一、先确认 2:1

中英混排的等宽字体，唯一不能妥协的是：一个汉字正好等于两个拉丁字符的宽度。做不到这点，`|` 画的表格、对齐的注释、`tree` 的输出全会歪。

判断方法很直接：在终端里打这两行，看第二行的竖线是否对齐第一行。

```
|--------|--------|
|中文占位|abcdefgh|
```

对不齐，说明这套字体的汉字不是拉丁的整两倍宽，或者终端按自己的规则重新算了宽度。

AKR 的八套字体里，编程面全部按严格 2:1 构建并在每次构建时过闸校验（`verify2to1`）；正文面（AKR Hand SC Text）反而**主动**去掉了等宽声明，因为它不是给终端用的。

## 二、再确认符号宽度

比 2:1 更隐蔽的一层是 East_Asian_Width。`…`、`—`、`≠` 这类符号在 Unicode 里被标为 Ambiguous 或 Wide，不同终端对它们的取宽不一样。字体如果不显式把这些字形做成半宽或全宽，光标位置就会跟渲染宽度对不上——表现出来就是「删一个字，光标少退一格」。

这一项没法靠肉眼看字形判断，只能看字体有没有明确说明自己处理过 EAW。

## 三、最后才是图标

Nerd Font 图标有两种打法：`--complete` 会把图标做成双宽，`--single-width-glyphs`（也就是 NFM，Nerd Font Mono）会压成单格。终端 prompt 里用双宽图标，就会把后面的字挤掉一格。

**在终端里用，认准 Mono / NFM 版本。**

## 四、上游选哪套，取决于你想要什么手感

以下是几套常见的中文开源字体，以及它们做成编程字体之后各自的性格：

| 上游 | 手感 | 做成编程字体后适合 |
| --- | --- | --- |
| [霞鹜文楷](/upstream/lxgw-wenkai) | 楷体，手写起收 | 读注释和文档舒服，长时间盯代码略轻 |
| [霞鹜新致宋](/upstream/lxgw-neozhisong) | 宋体，笔画对比明显 | 字形辨识度高，适合长会话 |
| [IBM Plex Sans SC](/upstream/ibm-plex-sans-sc) | 中性黑体 | 最不挑人，团队统一字体的默认选项 |
| [资源圆体](/upstream/resource-han-rounded) | 圆角 | 界面截图和演示里最讨喜 |
| [朱雀仿宋](/upstream/zhuque-fangsong) | 仿宋，细笔画斜势 | 有打字机质感，小字号要谨慎 |
| [缝合像素字体](/upstream/fusion-pixel) | 12px 点阵 | 复古终端，必须用 12 的整数倍字号 |
| [悠哉](/upstream/yozai) | 圆润随手 | 介于黑体和手写之间，轻松 |

拉丁那一侧同样有性格：Iosevka 窄、Lilex 中性带连字、Monaspace Radon 带手写倾斜、Courier Prime 是打字机。**中英两侧的手感要朝同一个方向倒**，否则一行里两种气质会打架——这也是 AKR Hand 要把汉字剪切 7.5° 去对上 Radon 倾角的原因。

## 五、自己试一遍

上面所有判断，最后都不如把自己的代码贴进去看一眼。[在线预览](/preview)里八套都能切，字号行高连字都能调，链接可以直接分享给同事。
